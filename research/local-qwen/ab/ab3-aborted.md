# `ab3` — aborted diagnostic run

Date: 2026-09-29

## Disposition

`ab3` is invalidated and has no benchmark verdict. It was deliberately stopped
during rep3 lean S2 when the diagnostic `danger-full-access` execution path
escaped the benchmark fixture and modified a real repository. Do not complete,
aggregate, or compare this run as if it were the registered 42-run experiment.

The incident is itself decisive safety evidence: `diagnostic-full` is useful
only for proving that the model and lean harness can execute tools when the
broken confined backend is removed. It is not a deployable permission mode and
must not be used for unattended Fleet sessions.

## Containment and recovery

- The runner, lean DSH, and tee were interrupted immediately.
- The remaining fake S5 server, PID 654797, was identified by its cwd as the
  `ab3/rep3/cc/sc5` fixture and stopped. Ports 8878, 3180, and 8899 are closed.
- The three attributed source/test changes and two generated bytecode files
  were removed/reverted. `git -C /home/ville/dev/aivan-contracts status
  --short` and `git diff --exit-code` are clean.
- `/tmp/calcsenv` was moved to the desktop trash. `/etc/ab-bench-probe.txt`
  does not exist.
- Qwen vLLM was not restarted or killed. PID 230853 remained healthy at
  `http://127.0.0.1:8001/v1/models` after containment.
- The temporary persona change that explicitly walked to `/` was reverted in
  both the installed lean preset and `lean-persona-draft.md`.

The venv-local `pip install` may have populated ordinary user pip cache entries;
those were not deleted because they are shared cache state and cannot be safely
attributed file-by-file. It did not install into the system interpreter.

## Production conclusion and next experiment

Keep `workspace-write`; do not promote `diagnostic-full`. On Linux the shipped
DSH sandbox selects a working `bwrap` first and Landlock second, and fails closed
if neither works. This WSL2 kernel successfully creates an unprivileged user
namespace, and Ubuntu offers `bubblewrap` 0.9.0, so bwrap is the first production
candidate. It is not currently installed, and installing it requires operator
sudo.

Before another full A/B:

1. Install `bubblewrap`, restart the DSH profile so backend selection is
   reprobed, and functionally verify allowed in-workspace writes plus denied
   out-of-workspace writes.
2. Tighten `str_replace_editor` from the current broad `/home/ville` allow-list
   to the immutable session workspace boundary. A shell sandbox alone does not
   constrain this separate filesystem tool.
3. Give S2 an actual repository marker and specify a bounded repo-root discovery
   rule; never instruct an agent to scan to `/`.
4. Run the shell/editor/gate smoke matrix, then S1/S2/S7. Freeze a new run id
   only after all containment probes pass.
